# FC ONLINE 전적 기반 전술 추천기

FC ONLINE 닉네임을 입력하면 NEXON Open API로 최근 공식 경기 데이터를 조회하고, 경기 요약과 플레이 성향, 규칙 기반 추천 전술을 보여주는 Next.js MVP입니다.

현재 단계는 조회 → 정규화 → 성향 분석 → 규칙 추천 흐름을 검증합니다. DB, 로그인, 랭커 분석, 학습 모델 기반 개인화는 포함하지 않습니다.

> **전술 호환성 상태:** 팀 전술은 12th Next Field의 공식 선택지·숫자 범위에 맞게 재설계했고 런타임 검증도 통과합니다. 다만 포메이션 프리셋명과 개인 전술·참여도는 현행 PC 클라이언트 수동 확인 전이므로 전체 결과는 `부분 검증`입니다. UI의 `미확인` 값을 완성 전술표로 간주하지 마세요.

## 제품 방향: 간편 모드

제품의 기본 경험은 **닉네임 입력 후 30초 안에 FC ONLINE에 옮겨 적을 수 있는 팀 전술 1개를 복사하는 것**입니다. 검색부터 추천까지 한 페이지에서 끝내고, 주전술과 복사 버튼을 먼저 보여줍니다. 대안 전술·성향 분석·최근 경기 상세·스키마 메타데이터는 접힌 상세 영역에 두며, 미확인 개인 전술은 기본 적용값과 복사 결과에서 제외합니다.

간결함 때문에 검증 상태를 숨기지는 않습니다. 확인되지 않은 포메이션·개인 전술은 `미확인`으로 알리고, 실제 PC 클라이언트 입력 증거 없이 `confirmed`로 바꾸지 않습니다. 현재 간편 모드 흐름은 구현돼 있지만 30초 목표 달성과 우선 3개 후보의 인게임 입력 가능성은 아직 사용자·클라이언트 검증 전입니다. 이 3개는 검증 우선순위이며, 공개 완료 전에는 나머지 도달 가능 후보도 검증하거나 추천 범위를 제한해야 합니다. 범위와 합격 기준은 [간편 모드 제품 명세](docs/simple-mode-product-spec.md)를 따릅니다.

## 현재 목적 달성 상태

**조회·분석·규칙 추천의 기술 MVP는 달성했지만, 현행 FC ONLINE에 그대로 옮길 수 있고 효과까지 검증된 전술 추천 제품은 아직 아닙니다.**

| 목표 | 상태 | 판단 근거 |
| --- | --- | --- |
| 닉네임으로 최근 공식 경기 조회 | 구현 | 서버 라우트, 오류·부분 성공 처리, 요청 보호와 테스트 존재 |
| 경기 응답 정규화와 플레이 성향 요약 | 구현 | 집계 지표와 결측 처리, 데이터 충분도 표시 존재 |
| 성향에 따른 주전술·대안 생성 | 구현 | 고정 임계값, 9개 버전형 템플릿과 7개 포메이션 후보의 규칙 엔진 존재 |
| 현행 팀 전술 입력 계약 | 코드 검증 완료 | 공식 열거형, `1~10`·`1~5`, `chanceCreation`, 런타임 검증 적용 |
| 포메이션·개인 전술 전체 이식 | 부분 검증 | 역할과 UI 값을 분리했지만 프리셋명·개인 메뉴·참여도는 클라이언트 확인 필요 |
| FC ONLINE에서 가능한 모든 전술 지원 | 범위 밖 | 현재 7개 후보는 전체 전술 공간이 아닌 제한된 부분집합 |
| 추천이 실제 성과를 높인다는 검증 | 미달성 | 실제 적용·배정 확률·후속 결과 로그와 타당한 실험이 아직 없음 |
| 실제 사용자 데이터 장기 저장 운영 | 미구현 | 현재 영구 DB는 없으며, 도입 전 30일 TTL·삭제·철회 절차가 필요 |

현재 제품은 `공식 팀 전술 스키마를 통과한 제한 후보 추천기` 단계입니다. 다음 이정표는 `balanced`, `attack-possession`, `defense-risk` 3개 후보의 포메이션·개인 전술을 PC 클라이언트에서 우선 검증하는 것입니다. 이후 나머지 도달 가능 후보를 검증하거나 추천 범위를 검증된 부분집합으로 제한해야 하며, 모든 전술 자동 생성과 승률 향상 주장은 별도 검증과 연구가 필요합니다.

## 실행 준비

1. Node.js 22.23.1과 npm 10.9.8을 준비합니다. 버전 관리 도구를 쓴다면 `.nvmrc`를 사용할 수 있습니다.
2. 잠금 파일 기준으로 의존성을 설치합니다.

```bash
npm ci
```

3. 환경변수 파일을 만듭니다.

```bash
cp .env.example .env.local
```

4. `.env.local`에 NEXON Open API 키를 입력합니다.

```env
NEXON_OPEN_API_KEY=발급받은_API_KEY
FC_ONLINE_DEFAULT_LIMIT=5
FC_ONLINE_TRUST_PROXY_HEADERS=false
```

API 키는 브라우저로 보내지 않고 서버 API 라우트에서만 `x-nxopen-api-key` 헤더로 사용합니다.

`FC_ONLINE_TRUST_PROXY_HEADERS`는 배포 프록시가 `x-forwarded-for`와 `x-real-ip`를 신뢰할 수 있게 덮어쓰는 환경에서만 `true`로 설정합니다. 로컬이나 직접 노출 서버에서는 기본값 `false`를 유지합니다.

## 실행과 검증

개발 서버:

```bash
npm run dev
```

브라우저에서 `http://localhost:3000`을 열고 FC ONLINE 닉네임을 입력합니다.

프로덕션 검증과 실행:

```bash
npm ci
npm run verify
npm start
```

`npm run verify`는 타입 검사, Vitest 전체 테스트, 프로덕션 빌드를 순서대로 실행합니다. GitHub Actions도 push와 pull request마다 같은 명령을 실행합니다.

배포 환경에는 `.env.local`을 올리지 말고 호스팅 서비스의 비밀 환경변수로 `NEXON_OPEN_API_KEY`를 설정합니다. 배포 전에는 CI 상태와 저장소 추적 파일에 API 키나 실제 캡처 응답이 없는지 확인합니다.

## 실제 API 성공 케이스 확인

1. `.env.local`에 실제 API 키를 넣습니다.
2. 개발 서버를 실행합니다.
3. 실제 닉네임을 검색합니다.
4. 조회 유저, 승·무·패 요약, 최근 공식 경기, 점수와 주요 지표가 표시되는지 확인합니다.

서버 API를 직접 호출할 수도 있습니다.

```bash
curl "http://localhost:3000/api/search?nickname=닉네임"
curl "http://localhost:3000/api/search?nickname=닉네임&limit=5"
```

`limit`은 `1~10` 범위로 보정되며 생략하면 `FC_ONLINE_DEFAULT_LIMIT`를 사용합니다.

실제 성공 응답을 로컬 검증용으로 캡처하려면 다음 명령을 사용합니다.

```bash
npm run capture:fixture -- "닉네임"
```

캡처 결과는 `src/lib/fconline/__fixtures__/captured/<캡처시각>`에 저장되고 Git 추적에서 제외됩니다.

`captured`에는 실제 NEXON Game Data가 들어갑니다. 현재 스크립트는 자동 만료·삭제를 구현하지 않으므로 캡처 시각을 기준으로 30일 이내 직접 삭제해야 하며, 공개 fixture로 복사하면 안 됩니다. 자세한 기준은 [NEXON Open API 데이터 처리 기준](docs/data-handling-policy.md)을 따릅니다.

## Fixture 구조

```text
src/lib/fconline/__fixtures__
├─ success
│  ├─ id.json
│  ├─ basic-user.json
│  ├─ match-ids.json
│  └─ match-details.json
└─ captured
   └─ <캡처시각>
      └─ 실제 API 키로 캡처한 로컬 검증용 JSON
```

- `success`에는 실제 이용자 응답을 복제하지 않고 사람이 구성한 단위 테스트용 합성 예시만 둡니다.
- `captured`는 실제 API 성공 응답을 저장하는 로컬 전용 공간입니다.
- 실제 응답에서 발견한 구조나 경계 사례를 테스트할 때는 값 전체를 사람이 다시 구성한 합성 fixture로 작성합니다. 닉네임과 OUID만 바꾼 실제 응답은 공개 fixture로 사용하지 않습니다.

## 데이터 흐름

```text
닉네임 입력
→ /api/search 서버 라우트
→ FC ONLINE Open API
   1. /id
   2. /user/basic
   3. /user/match
   4. /match-detail
→ normalizeSearchResult
→ SearchResult
→ analyzePlayStyle
→ PlayStyleAnalysis
→ recommendTactic
→ 최근 경기와 추천 카드 표시
```

원본 API 응답은 `normalize.ts`에서 화면·분석용 `SearchResult`로 축소합니다. 성향 분석기는 정규화된 경기만 입력받고, 전술 추천기는 `PlayStyleAnalysis`만 입력받습니다. 이 경계를 유지해 원본 API, 정규화, 분석, 추천 계약을 분리합니다.

서버 라우트는 동일 닉네임·경기 수 요청을 진행 중에는 하나로 합치고 완전한 성공 결과만 15초 동안 메모리에 캐시합니다. 외부 요청은 8초 제한을 가지며, 경기 상세 일부가 실패하면 성공한 경기만 사용하되 429·503·시간 초과 시 추가 상세 호출을 중단합니다.

## 성향 분석

성향 분석은 `src/lib/analysis/playStyleAnalyzer.ts`에서 처리합니다. 각 결과는 `label`, `score`, `reason`을 포함합니다. 복합 성향에 필요한 지표가 하나라도 없으면 `score`는 `null`이고 화면에는 `정보 부족`으로 표시됩니다.

| label | 현재 MVP 계산 기준 |
| --- | --- |
| 공격적 | 슈팅 `4→0점, 8 이상→100점`과 드리블 `8→0점, 18 이상→100점`을 선형 계산한 뒤 평균 |
| 수비 불안 | 실점 `0.8→0점, 2 이상→100점`과 태클 성공률 `75→0점, 55 이하→100점`을 선형 계산한 뒤 평균 |
| 득점력 높음 | 득점 `0.8→0점, 2 이상→100점`과 유효 슈팅 `2→0점, 5 이상→100점`을 선형 계산한 뒤 평균 |
| 점유율 지향 | 점유율 `45→0점, 53 이상→100점`으로 선형 계산 |
| 슈팅 빈도 높음 | 슈팅 `4→0점, 8 이상→100점`으로 선형 계산 |

모든 점수는 `0~100`으로 고정되므로 목표값을 넘으면 다시 낮아지지 않고 100점에 포화됩니다. 기본 5경기 요청에서는 각 지표에 유효 표본이 최소 3개 있어야 하며, 복합 성향은 같은 경기에서 두 구성 지표가 모두 있는 표본도 최소 3개여야 합니다. 요청 경기 수가 1~2이면 최소 표본 수도 그 요청 수로 낮아집니다.

기준값은 MVP 검증용 상수이며 데이터로 검증된 사용자 유형이나 추천 효과를 뜻하지 않습니다.

응답 필드명은 현재 `confidence`이지만 그 안의 `level`과 `coverage`는 **추천 적중 확률이 아니라 데이터 충분도 정보**입니다. 경기 수나 지표 coverage가 낮으면 정보 부족 안내를 표시합니다. 명칭과 통계적 불확실성 처리의 개선 방향은 [연구·검증 로드맵](docs/research-validation-roadmap.md)에 정리돼 있습니다.

## 추천 규칙

전술 추천은 `src/lib/tactics/tacticRecommender.ts`에서 주전술 1개와 대안 전술 1개를 만듭니다. 위에서 먼저 일치하는 규칙이 주전술이 되며, 수비 위험 보정 규칙을 우선합니다. 대안은 다른 포메이션의 다음 일치 규칙을 사용하고 없으면 기본 후보를 반환합니다.

| 규칙 | 조건 | 현재 후보 포메이션 |
| --- | --- | --- |
| 수비 보정 점유 | `수비 불안 >= 70`, `점유율 지향 >= 65` | `4-1-4-1` |
| 수비 보정 역습 | `수비 불안 >= 70`, `공격적 >= 70` | `5-2-3` |
| 공격 점유 압박 | `공격적 >= 70`, `점유율 지향 >= 70`, `수비 불안 <= 69` | `4-3-2-1` |
| 투톱 슈팅 강화 | `공격적 >= 70`, `슈팅 빈도 높음 >= 70` | `4-2-2-2` |
| 점유 득점 유지 | `점유율 지향 >= 70`, `득점력 높음 >= 70` | `4-3-3 홀딩` |
| 점유 전개 유지 | `점유율 지향 >= 70` | `4-3-3 홀딩` |
| 수비 안정 우선 | `수비 불안 >= 70` | `4-1-4-1` |
| 기본 밸런스 | 위 조건에 해당하지 않음 | `4-4-2` |
| 안정 점유 대안 | 기본 밸런스의 대안 | `4-2-3-1` |

현재 후보 7개는 FC ONLINE에서 가능한 전체 전술 공간이 아니라 프로젝트가 선택한 부분집합입니다.

### 현재 인게임 호환성 상태

구형 숫자와 명칭은 폐기하고 의미에 따라 다시 설계했습니다.

- 수비 폭·깊이·공격 폭·크로스 시 박스 진입 성향은 정수 `1~10`, 코너킥·프리킥은 정수 `1~5`만 허용합니다.
- 팀 성향 7개, 수비 스타일 5개, 공격 스타일 4개를 제한 타입과 런타임 검증으로 고정합니다.
- 수비 지역 `buildUpPlay`와 공격 지역 `chanceCreation`을 별도 저장하고 화면에 표시합니다.
- 각 추천에 스키마·게임 패치·템플릿 ID와 버전, SHA-256 설정 해시, 검증 상태를 포함합니다.
- 역할 설명과 실제 개인 전술 후보를 분리하고, 클라이언트에서 확인되지 않은 메뉴값과 참여도는 `confirmed: false`로 표시합니다.
- 포메이션 프리셋명과 개인 전술은 아직 `unconfirmed`, 전체 결과는 `partial`입니다.
- 빠른 공격·수비 전술은 저장형 팀 전술이 아닌 상황별 명령이므로 현재 추천 범위에서 제외합니다.

정확한 계약과 전체 호환 완료 조건은 [전술 스키마와 호환성 기준](docs/fc-online-tactic-schema.md)을 봅니다.

## 실사용 검증

[실사용 테스트 기록 양식](docs/user-test-record-template.md)을 사용합니다.

- 소수 경기 테스트는 조회 성공, 인게임 이식 가능성, 설명 이해도를 확인하는 스모크 테스트입니다.
- 전술별 경기 결과를 비교할 때는 실제 적용 여부, 게임 모드, 상대 수준, 패치, 적용 순서를 기록합니다.
- 추천 전후 차이를 곧바로 추천의 효과로 표현하지 않습니다.
- 추천 효과 실험 전에는 모든 후보가 자동 팀 전술 검증과 포메이션·개인 전술 수동 입력 검증을 모두 통과해야 합니다.

## NEXON 데이터 보존과 개인정보

- API로 조회한 원본과 그 파생값에는 `pulled_at`과 30일 이내의 `expires_at`을 두고, 만료 시 원본·정규화 결과·집계·로그·캐시·백업을 삭제합니다.
- 가명 ID는 익명 데이터가 아니며, 실제 matchId·OUID·닉네임과 매핑표를 공개 저장소에 넣지 않습니다.
- 계속 필요한 데이터는 보존 기간을 연장하지 않고 API에서 다시 조회합니다.
- 외부 사용자 대상 운영 전에는 열람·정정·삭제·철회 절차와 실제 처리에 맞는 개인정보처리방침을 구현합니다.
- 공개 테스트 fixture는 합성 데이터만 사용합니다.

구체적인 수명주기와 현재 미구현 배포 게이트는 [NEXON Open API 데이터 처리 기준](docs/data-handling-policy.md)에 정리했습니다. 기준은 [NEXON Open API 이용약관](https://openapi.nexon.com/support/)의 최신 내용을 우선합니다.

## API 보호와 운영 경계

- 닉네임은 공백 제거 후 최대 30자로 검증합니다.
- 캐시와 진행 중 동일 요청을 확인한 뒤 실제 새 검색만 상류 API 호출량 `3 + limit`을 선예약하며 프로세스 전체 예산은 분당 120 호출 단위입니다.
- 실제 상류 요청 시작은 프로세스 전체에서 초당 최대 8회 간격으로 직렬화하고 대기열은 200개로 제한합니다.
- 대기 시간도 8초 제한에 포함하며 429 응답의 `Retry-After` 동안 다음 요청 시작을 늦춥니다.
- `FC_ONLINE_TRUST_PROXY_HEADERS=true`이면 검증된 클라이언트 IP별 분당 10회 제한도 적용합니다.
- 캐시, 요청 병합, 요청 제한 상태는 프로세스 메모리에만 있습니다. 여러 서버 인스턴스에서는 Redis 같은 공유 저장소로 교체해야 합니다.
- 공격자가 프록시 헤더를 직접 보낼 수 있는 환경에서는 `FC_ONLINE_TRUST_PROXY_HEADERS`를 켜면 안 됩니다.
- 외부 API 원문 오류와 서버 환경변수 이름은 공개 응답에 포함하지 않습니다.

## 에러 구분

| type | 상황 | 사용자 메시지 예시 |
| --- | --- | --- |
| `validation` | 닉네임이 비어 있음 | FC ONLINE 닉네임을 입력해 주세요. |
| `configuration` | API 키 설정 누락 | 서버 설정이 완료되지 않았습니다. |
| `external-api` | 외부 API 실패, 시간 초과 또는 호출 제한 | 잠시 뒤 다시 시도해 주세요. |
| `empty-result` | 최근 공식 경기 또는 상세 결과 없음 | 최근 공식 경기 기록을 찾지 못했습니다. |

화면은 서버에서 정규화한 사용자용 메시지만 표시하며 비JSON 응답이나 기술 예외 문구는 일반 오류 안내로 대체합니다.

## 현재 구현 범위

- 한 페이지에서 주전술을 우선 제시하고 검증된 팀 전술을 복사하는 간편 모드
- 대안 전술·성향 분석·최근 경기·메타데이터·미확인 개인 전술의 단계적 상세 표시
- 닉네임 기반 유저와 최근 공식 경기 조회
- 경기 상세 조회와 화면용 응답 정규화
- 집계 지표 기반 플레이 성향 분석
- 성향 결과 기반 규칙 전술 추천과 주전술·대안 쌍 검증
- 12th Next Field 팀 전술 제한 타입과 런타임 검증
- 전술 스키마·패치·템플릿 메타데이터, 설정 해시와 부분 검증 상태
- 역할 설명, 실제 UI 후보와 참여도 확인 상태 분리
- 데이터 coverage 안내
- 요청 취소, 오류, 부분 성공 처리
- 메모리 캐시, 동시 요청 병합, 상류 호출 제한
- 성공 응답 전체 구조의 공유 런타임 검증
- API·라우트·정규화·성향·전술 추천 단위 테스트
- GitHub Actions 검증 워크플로
