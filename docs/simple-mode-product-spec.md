# 간편 모드 제품 명세

상태: **UI 흐름 구현 완료, 사용성·PC 클라이언트 검증 전**

## 제품 목표

사용자가 FC ONLINE 닉네임을 입력한 뒤 **30초 안에 실제 게임에 옮겨 적을 준비가 된 팀 전술 1개를 복사**하게 합니다.

한 페이지에서 다음 흐름을 끝냅니다.

```text
닉네임 입력 → 최근 경기 조회 → 주전술 확인 → 전술 복사 → FC ONLINE에 입력
```

30초는 검색 제출부터 클립보드 복사 성공까지의 목표 시간입니다. 게임 안에서 값을 모두 입력하는 시간은 별도의 `입력 가능성` 검증으로 측정합니다.

## 기본 화면 원칙

기본 화면에는 결정과 적용에 필요한 정보만 둡니다.

- 주전술 1개와 짧은 추천 이유를 가장 먼저 보여줍니다.
- 복사 버튼은 주전술 가까이에 두고 복사 성공·실패를 즉시 알립니다.
- 복사 결과에는 검증된 팀 전술 값을 게임에서 따라 입력하기 쉬운 순서로 포함합니다. 포메이션 후보를 문맥상 함께 적는 경우 `클라이언트 미확인`임을 같은 줄에 표시합니다.
- 대안 전술, 성향 분석, 최근 경기 상세, 스키마·패치·해시 메타데이터는 접힌 상세 영역에 둡니다.
- 미확인 개인 전술·참여도는 기본 적용값과 복사 결과에서 제외합니다. 포메이션 후보는 검증된 입력값과 시각적으로 구분합니다.
- 미확인 값을 숨기더라도 `부분 검증` 상태와 제외 이유는 주전술 근처에서 짧게 알립니다.

접힌 상세 영역은 감사와 개발 검증을 위한 보조 수단입니다. 펼쳤을 때도 미확인 값을 검증된 입력값처럼 표현하지 않습니다.

## 비목표

- 가능한 모든 포메이션과 개인 전술을 한 번에 지원하지 않습니다.
- 분석 지표와 기술 메타데이터를 기본 화면의 중심으로 만들지 않습니다.
- 추천 전후 승률 차이를 추천의 인과 효과나 승률 향상 보장으로 표현하지 않습니다.
- 실제 PC 클라이언트 증거 없이 `confirmed` 상태를 부여하지 않습니다.
- 간편함을 이유로 데이터 부족이나 부분 검증 상태를 감추지 않습니다.

## 검증 경계와 우선 검증 3개

팀 전술 필드의 공식 열거형·숫자 범위와 응답 구조는 코드에서 검사합니다. 포메이션 프리셋명, 슬롯 배치, 개인 전술 메뉴와 참여도는 현행 PC 클라이언트의 수동 검증 대상입니다. 상세한 계약은 [전술 스키마와 호환성 기준](fc-online-tactic-schema.md)을 따릅니다.

첫 수동 검증 묶음은 성격이 겹치지 않는 다음 3개입니다.

| 용도 | 템플릿 ID | 포메이션 후보 |
| --- | --- | --- |
| 기본 | `balanced` | `4-4-2` |
| 공격 | `attack-possession` | `4-3-2-1` |
| 수비 보정 | `defense-risk` | `4-1-4-1` |

이 3개는 **검증 우선순위이지 현재 추천기의 허용 목록이 아닙니다.** 현재 `recommendTactic`은 규칙 7개와 기본·대안 템플릿을 합쳐 9개 ID를 결과에 낼 수 있습니다. 따라서 우선 3개만 통과한 상태를 간편 모드 완료로 보지 않습니다. 공개 추천 흐름을 완전 검증하려면 도달 가능한 9개를 모두 확인하거나, 코드를 검증된 부분집합만 추천하도록 제한해야 합니다.

우선 검증 3개도 아직 완전한 인게임 전술로 검증되지 않았습니다. 자동 테스트 통과나 공식 범위 일치는 실제 입력 성공의 대체 증거가 아닙니다. 다음 자료가 후보별로 남기 전에는 포메이션·개인 전술을 `confirmed`로 선언하지 않습니다.

1. 검증한 게임 패치와 날짜
2. 포메이션 프리셋명과 슬롯 배치의 실제 선택 기록
3. 노출한 모든 개인 전술·참여도의 포지션별 입력 성공 기록
4. 복사 내용과 PC 클라이언트 입력값의 일치 확인
5. 검증자와 재현 절차가 포함된 [실사용 테스트 기록](user-test-record-template.md)

수동 검증은 `우선 3개 전체 입력 성공 → 복사 순서와 문구 보정 → 나머지 6개 검증 또는 추천 범위 제한` 순으로 진행합니다. 일부 필드만 확인한 경우 전체 후보가 아니라 해당 필드만 확인된 것으로 기록합니다.

## 성공 기준

| 지표 | 측정 방법 | 합격 기준 |
| --- | --- | --- |
| 검색→복사 시간 | 검색 제출부터 클립보드 성공 알림까지 측정하며 API 대기 시간도 포함 | 사용성 검증의 중앙값 30초 이하 |
| 복사 성공 | 복사 시도 대비 클립보드 성공 알림 비율과 실패 복구 여부 확인 | 지원 브라우저 반복 테스트 100%, 사용자 검증 95% 이상 |
| 입력 가능성 | 복사한 각 값을 현행 PC 클라이언트에서 그대로 찾고 입력 | 1차로 우선 3개, 공개 완료 시 도달 가능한 후보 전체의 노출값 100% 입력 성공 |
| 이해도 | 도움 없이 주전술, 추천 이유, 미확인 범위를 설명할 수 있는지 확인 | 검증 참여자 80% 이상이 세 항목을 정확히 설명 |

사용성 표본 수와 환경은 결과와 함께 공개합니다. 작은 표본의 통과를 일반 사용자 전체의 성과나 추천 효과로 확대 해석하지 않습니다.

## 완료 조건

간편 모드는 다음 조건을 모두 만족할 때 제품 목표를 달성한 것으로 봅니다.

- 닉네임 입력부터 주전술 복사까지 한 페이지에서 완료됩니다.
- 주전술이 기본 노출되고 대안·분석·최근 경기·메타데이터·미확인 개인 전술은 접혀 있습니다.
- 복사 성공·실패 피드백과 키보드·모바일 동작을 포함한 자동·브라우저 검증이 통과합니다.
- 우선 3개를 포함해 공개 추천 흐름에서 도달 가능한 모든 후보가 같은 현행 패치의 PC 클라이언트에서 전부 입력되고 증거가 기록됩니다. 일부만 검증할 경우 추천 범위를 그 부분집합으로 제한합니다.
- 위 네 가지 성공 지표가 합격 기준을 충족합니다.
- 미확인 개인 전술·참여도는 복사 결과에서 제외되고, 포메이션을 포함한 모든 상태 문구와 실제 `confirmed` 값이 일치합니다.
- 패치나 전술 선택지가 바뀌면 관련 후보를 다시 `unconfirmed`로 돌리고 재검증합니다.

이 조건은 사용 편의와 입력 호환성의 완료 기준입니다. 추천이 경기 성과를 높인다는 결론은 별도이며, [논문 적용 및 추천 효과 검증 로드맵](research-validation-roadmap.md)의 로그·실험 절차를 통과해야 합니다.
