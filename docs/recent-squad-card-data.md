# 최근 사용 선수 카드와 능력치 연결 기준

## 결론

이 프로젝트는 최근 공식 경기에서 사용된 선수 카드의 `spId`, 강화 단계, 등록 포지션과 경기 활약을 표시합니다. 이는 **현재 보유 선수단이나 현재 저장된 스쿼드가 아니라 최근 경기 명단**입니다.

카드 고유 능력치는 NEXON Open API가 제공하지 않습니다. 따라서 서버가 데이터센터나 제3자 사이트를 자동 수집하지 않고, 카드별로 사용자가 직접 여는 FC ONLINE 공식 데이터센터 상세 링크를 제공합니다. 카드 능력치가 정식 API 또는 사용 허가가 명확한 데이터로 확보되기 전까지 선수 카드는 전술 추천 입력으로 사용하지 않습니다.

## 확인 가능한 범위

| 정보 | 출처 | 제품 표시 | 해석 |
| --- | --- | --- | --- |
| 최근 경기 카드 ID | `match-detail.player[].spId` | 표시 | 해당 경기 응답에 포함된 카드 |
| 강화 단계 | `match-detail.player[].spGrade` | 표시 | 해당 경기 카드의 강화 단계 |
| 등록 포지션 | `match-detail.player[].spPosition` + `spposition.json` | 표시 | `SUB`는 후보 명단이며 실제 교체 출전을 확정하지 않음 |
| 선수명 | `spid.json` | 표시 | 공식 선수 메타데이터 |
| 시즌명·시즌 이미지 | `seasonid.json` | 표시 | `spId`에서 해석 가능한 공식 시즌 메타데이터가 있을 때만 표시 |
| 평점·골·도움 등 | `player[].status` | 최근 경기 활약으로 표시 | 카드 고유 능력치가 아니라 해당 경기 기록 |
| 카드·강화 기준 능력치 | 공식 데이터센터 | 외부 링크 | 사용자가 직접 확인하며 추천에는 미반영 |
| 팀컬러·적응도·훈련코치가 적용된 최종 능력치 | 제공되지 않음 | 표시하지 않음 | API만으로 복원하거나 단정할 수 없음 |
| 현재 보유 카드·현재 저장 스쿼드 | 제공되지 않음 | 표시하지 않음 | 최근 경기 명단과 구분 |

공식 문서:

- [매치 상세 기록 조회](https://openapi.nexon.com/ko/game/fconline/?id=3)
- [선수·시즌·포지션 메타데이터](https://openapi.nexon.com/ko/game/fconline/?id=5)
- [선수 이미지 정보](https://openapi.nexon.com/ko/game/fconline/?id=6)
- [NEXON Open API 이용약관](https://openapi.nexon.com/support/)

## 사용자 화면

주전술과 복사 버튼을 먼저 보여주는 간편 모드의 우선순위는 유지합니다. 그 아래의 `최근 사용 선수단 보기`를 펼치면 다음을 확인할 수 있습니다.

- 선수명·시즌·강화 단계·주 등록 포지션
- 최근 명단 경기 수와 선발 위치 경기 수
- `player.status` 기반 평균 평점·골·도움
- 공식 선수 이미지
- 해당 `spId`와 강화 단계로 여는 `공식 능력치 보기` 링크

메타데이터 호출이 실패해도 닉네임 조회와 기존 전술 추천은 성공합니다. 이때 이름·시즌·포지션 일부를 ID로 표시하고 장애 안내를 노출합니다. 선수 배열 자체가 없으면 선수단 정보 없음과 기존 경기 성향 기준 추천임을 알립니다.

## 데이터 흐름

```text
NEXON /match-detail
  → 조회 사용자의 player[]만 선택
  → 카드 ID·강화·포지션과 경기 status 정규화
  → spId + spGrade 단위로 최근 경기 집계
  → 공식 spid / seasonid / spposition 메타데이터 결합
  → 최근 사용 선수단 접힌 영역 표시
  → 사용자가 원할 때만 공식 PlayerInfo 페이지로 이동
```

정규화는 손상된 선수 한 명만 제외하며 경기 전체를 버리지 않습니다. 같은 경기에서 같은 `spId + spGrade`가 중복되면 한 번만 집계하고, 같은 선수라도 강화 단계가 다르면 별도 카드로 구분합니다. 대표 포지션 동률은 더 최근 경기의 값을 우선합니다.

시즌은 현재 `spId`의 상위 자릿수를 공식 `seasonid.json`에 대조해 찾습니다. 이 자릿수 규칙은 문서화된 독립 계약이 아니므로 일치하는 공식 시즌 항목이 없으면 추정 이름을 만들지 않고 `시즌 정보 없음`으로 폴백하며, 전술 추천은 이 값에 의존하지 않습니다.

## 능력치 자동 수집을 하지 않는 이유

FC ONLINE 데이터센터에는 카드 능력치가 있지만, 능력치 화면용 내부 요청은 문서화된 Open API가 아닙니다. [NEXON Open API 이용약관 제8.15조](https://openapi.nexon.com/support/)는 정식 API로 허용된 경우 외의 NEXON 게임·서비스·웹사이트 대상 데이터 마이닝, 스크래핑, 크롤링과 자동 질의를 금지합니다. 따라서 다음은 운영 코드에 넣지 않습니다.

- FC ONLINE 데이터센터 HTML 또는 내부 화면용 요청 자동 수집
- 인벤·FCBeta·FCON.GG 등 제3자 선수 DB의 무허가 자동 수집·재배포
- 출처·갱신 시점·강화 반영 기준이 불명확한 능력치를 추천 근거로 사용

현재 상세 주소는 사용자 이동 링크로만 생성합니다.

```text
https://fconline.nexon.com/DataCenter/PlayerInfo?spid={spId}&n1Strong={spGrade}
```

정식 능력치 공급 계약이나 공개 API가 생기면 별도 공급자 계층으로 연결합니다. 그때도 `source`, `fetchedAt`, 강화 반영 여부, 패치 버전, 팀컬러·적응도 미반영 여부를 응답에 포함하고, 충분한 커버리지와 회귀 검증을 통과한 경우에만 추천의 보조 입력으로 사용합니다.

## 캐시와 보존

- 공식 정적 메타데이터 성공 결과: 프로세스 메모리에서 24시간 캐시
- 24시간 갱신 실패: 마지막 정상본을 최초 만료 후 최대 7일 동안 사용하고 1분 간격으로 재시도
- 정상본이 없는 공식 메타데이터 실패 결과: 장애 중 반복 호출을 막기 위해 1분 캐시
- 닉네임 검색 성공 결과: 기존 정책대로 15초 캐시
- 실제 경기·선수 파생 데이터: 장기 저장 도입 시 기존 30일 TTL·삭제·철회 범위에 포함

장애 폴백을 포함해도 정상본은 조회 후 8일을 넘기지 않으므로 Open API 데이터의 30일 이내 갱신 의무보다 짧습니다. 현재 영구 DB에는 저장하지 않습니다.

## 추천 반영 상태

응답의 `squadProfile.recommendationImpact`는 다음 계약을 갖습니다.

```json
{
  "applied": false,
  "reason": "정식 Open API가 카드 고유 능력치를 제공하지 않아 선수 카드는 확인용으로만 표시하고, 추천은 기존 경기 성향만 사용했습니다."
}
```

즉, 이번 기능으로 사용자에게 실제 사용 카드라는 추가 증거는 제공하지만 추천 규칙의 결과는 바꾸지 않습니다. 이 경계 덕분에 공식 메타데이터 장애나 능력치 미확보가 기존 전술 추천을 왜곡하지 않습니다.

## 검증 항목

- 숫자·숫자 문자열 정규화, 실제 0 기록 보존
- 손상된 `spId`만 제외하고 경기 유지
- 같은 카드 중복 방어와 강화 단계별 분리
- `SUB`와 선발 위치 분리, 대표 포지션 결정 순서
- 공식 메타데이터 3종 병렬 조회, 전체 항목 깊은 검증, 성공·실패 캐시
- 메타데이터 장애 시 검색 `200`과 기존 추천 유지
- 신규 응답 깊은 검증과 구형 성공 응답 호환
- 공식 이미지·데이터센터 URL의 출처 제한
- 데스크톱·모바일 접힌 선수단 영역과 기존 복사 흐름
